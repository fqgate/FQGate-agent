# MCP Apps 发布规范

MCP Apps 与 FQGate 主程序分别更新。只要页面继续使用主程序已经提供的接口，新增或调整页面不需要重新打包 FQGate。

## 目录结构

公开仓库中的稳定通道采用以下结构：

```text
fqgate/mcp-apps/
├─ stable.json
├─ stable.sig
└─ releases/
   └─ 0.1.0/
      ├─ manifest.json
      ├─ manifest.sig
      └─ index.html
```

`stable.json` 只负责定位稳定版本清单：

```json
{
  "schemaVersion": 1,
  "component": "fqgate-mcp-apps",
  "channel": "stable",
  "bundleVersion": "0.1.0",
  "manifest": "releases/0.1.0/manifest.json"
}
```

版本清单记录最低 FQGate 版本，以及每个逻辑页面的资源地址、接口绑定；所有逻辑页面共享同一份 `index.html`，其文件大小和 SHA-256 记录在每个条目中并且必须一致。清单不能配置交易权限、仅界面可用策略或网页访问范围；这些安全策略始终由 FQGate 主程序控制。

## 签名格式

- 签名算法固定为 Ed25519。
- 分别对 `stable.json` 和版本 `manifest.json` 的原始 UTF-8 字节签名，不能重新排版后再验签。
- `.sig` 文件保存 Base64 编码的 64 字节 detached signature，末尾允许一个换行符。
- 私钥只能通过 `--signing-key-file` 显式路径或 `FQGATE_MCP_APPS_ED25519_PRIVATE_KEY` 环境变量传入。
- 发布脚本不得生成、复制或提交正式私钥；缺少私钥时正式发布必须失败。

## 发布步骤

1. 在 `AI-plugins/ui-apps/mcp-apps/apps.json` 更新独立的 `bundleVersion` 和最低 FQGate 版本。
   稳定通道只接受 `主版本.次版本.修订号`，不能发布带 `beta`、`rc` 等后缀的预发行版本。
2. 运行全部 MCP Apps 测试；测试必须同时覆盖 HTTP 预览入口和 MCP 宿主入口使用的同一份 `index.html`。
3. 从公开仓库根目录生成正式包：

   ```powershell
   npm run release:mcp-apps -- --signing-key-file D:\安全目录\mcp-apps-private.pem
   ```

4. 核对版本目录、两个签名和所有页面校验值。
5. 同一份目录同时发布到 Gitee 和 GitHub；FQGate 下载时优先使用 Gitee，无法取得资源时回退 GitHub。

FQGate 的 Windows 与 macOS 安装包不预置任何 MCP App。正式页面只通过本目录的稳定通道独立发布，由主程序在线下载、验签并写入当前用户的数据目录。发布 MCP Apps 不需要重新打包主程序。

版本目录一经生成不得覆盖。需要修改时提升 `bundleVersion` 后重新发布。
